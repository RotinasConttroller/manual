Backup Database

O IBExpert Serviços de menu item de backup de banco de dados permite que você crie um backup ou cópia do banco de dados , salvando-o para o arquivo. Esta cópia do banco de dados pode ser mantido simplesmente por razões de segurança, ou restaurado pelos motivos apresentados em Por que é um backup de banco de dados e restaurar importante? .

Este item de menu é a janela de gestão para o API Services. Aqui você pode especificar tudo o que você também pode fazer na linha de comando usando o GBAK . Para automatizar o seu backup e restaurar usar o IBExpertBackupRestore serviço encontrado no menu Serviços IBExpert item HK-Software Serviços do Centro de Controle .

Um backup de banco de dados pode ser realizada sem a necessidade de desligar o banco de dados, os usuários poderão continuar seu trabalho comoFirebird / InterBase ® usa sua arquitetura multi-geracional para tirar um instantâneo do banco de dados em um momento em que seja solicitada a cópia de segurança. Todas as informações geradas pelo comprometidos transações e presente neste momento, é feito o backup.

Primeiro, selecione o banco de dados para o backup da lista drop-down de bases de dados registrados. Em seguida, selecione um nome de arquivo de backup existente, ou adicionar um novo arquivo de backup usando o Insert File (key ou [Ins]) ícone.

O botão [...] para a direita desta linha permite que você encontrar um arquivo existente ou especificar a unidade, caminho e nome do arquivo de backup para um novo arquivo. Por favor, note que IBExpert só irá criar um nome de arquivo no servidor, e não localmente (como acontece com GBAK), pois IBExpert utiliza os serviços API . Um backup local só pode ser realizada usando GBAK . Os sufixos . GBK e . FBK são tradicionalmente utilizados, respectivamente, para InterBase ® e arquivos de backup do Firebird. Um tamanho de arquivo só precisa ser especificado quando se trabalha com arquivos secundários . Todos os arquivos em um banco de dados multi-arquivo são copiados (ou seja, os dois arquivos secundários earquivos de sombra ). Firebird / InterBase ® compreende as ligações que existem com arquivos de dados secundários e de sombras. Considerando que o backup do sistema operacional funciona em uma base arquivo por arquivo, Firebird / InterBase ® sempre faz o backup de todos os arquivos em um banco de dados.

Opções de backup

●Ignorar verificação soma: Se esta opção estiver marcada, marque erros de soma no banco de dados páginas de cabeçalho , onde aspropriedades de conexão do banco de dados são armazenados, são ignoradas no backup. Como Firebird e InterBase ® normalmente abortar o backup quando verificar erros de soma são descobertos, esta é uma maneira de forçar um backup quando há problemas. Note-se que as versões do UNIX não utilizam somas de verificação.

●Ignorar transações em Limbo: Se esta opção estiver marcada, as transações em limbo , ou seja, operações que não podem ser definidos como executado ou abortado, são ignorados no backup. Apenas os mais recentes transações, comprometidos são copiados. Ele permite que um banco de dados para backup, antes de recuperar transações corrompido. Geralmente no limbo deve ser recuperado antes de um backup é realizado.

●Metadados Backup só: Se esta opção estiver marcada, apenas a definição do banco de dados (ou seja, a metadados , que fornece uma cópia vazia do banco de dados) é salvo. (Se for necessária uma cópia do banco de dados com um determinado conteúdo de dados, então use o IBExpertExecutivo Script ).

●Coleta de lixo: Se esta opção estiver marcada, a coleta de lixo é executado durante o backup. Ao desativar esta opção, o backup pode ser acelerado consideravelmente. (Consulte a coleta de lixo para mais informações.)

●Descrição velho metadados: Se esta opção estiver marcada, antigas descrições de metadados são incluídos no banco de dados de backup. Isso está incluído por razões de compatibilidade para idosos InterBase ® versões.

●Converter para Tabelas: Esta opção converte os dados do banco de dados para tabelas do backup. Trata-se ficheiros externos. É possível, emFirebird / InterBase ® para criar uma tabela como um arquivo externo - esta opção converte-los em tabelas de banco de dados internos.

●Prevenir banco de dados / transação desencadeia a partir de disparo: adicionado no IBExpert versão 2013/02/15. Este é igual aoisc_dpb_no_db_triggers opção em parâmetros de ligação adicionais .

●Formato: . Selecione o formato de dados para o arquivo de banco de dados de backup transportável é a opção padrão recomendado, pois permite uma restauração em diferentes Firebird / InterBase ® versões se desejava, ou seja, ele salva os dados e metadados em um formato genérico, ao contrário do opção não-transportável . (Por favor, note que quando o backup ea restauração, por exemplo, a partir de InterBase ® 4 para Firebird 1.5, procedimentos armazenados são restaurados como blobs , de modo que eles não podem trabalhar inicialmente).

●Detalhado: Verificação detalhado fornece um protocolo detalhado do processo de backup de banco de dados atual por escrito informações sobre o status passo-a-passo para o registro de saída.

Selecione a opção On Screen ou em arquivo para o log (não esquecendo de selecionar ou especificar um nome de arquivo para este protocolo). Esta opção é útil se o backup está falhando ea razão pela qual precisa ser analisado.

Em seguida, iniciar o backup. Se a opção de protocolo On Screen foi selecionado, o backup é registrado na saída da página.

Usando o IBExpert item de menu Banco de Dados / Database Informações de Registro , padrão de backup nomes de arquivos, caminhos e discos podem ser especificados se desejava, juntamente com o padrão de backup e restauração. Esta informação pode ser especificado quando inicialmente registrar um banco de dados no IBExpert (ver Register banco de dados ) ou numa data posterior (ver Informações de Registro de Banco de Dados ).

Em circunstâncias normais, o backup deve ser executado sem problemas, sem qualquer das opções acima tenham que ser verificado. Se, no entanto, os dados corrompidos ou danificados é suspeito ou problemas foram encontrados, alterar o formato de não-transportável e confira as opções deignorar o Sum e Ignore transações em Limbo . Embora isso não vai fornecer a compressão de dados de costume, ele fornece uma cópia completa do banco de dados, o que é importante antes de começar a repará-lo.

Também é possível validar o banco de dados usando Serviços / validação de banco de dados ou GFIX , antes de tentar novamente.

Para automatizar o processo de backup / restauração para seus bancos de dados, o uso do Service Center a HK-Software IBExpertBackupRestoreferramenta de servidor. IBExpertBackupRestore é um utilitário abrangente, fornecendo backup automático e restaurar instalações para Firebird eInterBase ® bases de dados com compactação de arquivos de backup mesmo uma opção para enviar automaticamente backup / restauração de arquivos de log.

Por que é um backup de banco de dados e restaurar importante?

Realizar backups regulares protege contra falhas de hardware e corrupção de dados , o que não pode ser fixado pelas Firebird / InterBase ®ferramentas de manutenção. É importante usar o Firebird / InterBase ® backup e restaurar as instalações, embora a maioria das redes incluem uma facilidade para backup e restauração de dados através da rede, porque:

●Backups do sistema operacional exigem acesso exclusivo ao banco de dados. O Firebird / InterBase ® Backup corre em paralelo com acessos de banco de dados simultâneas por outros usuários. Firebird / InterBase ® usa sua arquitetura multi-geracional para tirar um instantâneo do banco de dados em um momento no tempo para o backup. Todas as informações geradas pelo comprometidos transações e apresentar neste momento é feito o backup.

●Todos os arquivos em um banco de dados multi-arquivo são copiados. Firebird / InterBase ® compreende as ligações entre os diferentes arquivos de banco de dados e sombras . Os processos de backup do sistema operacional arquivos um após o outro e salva-los para o arquivo ou meio especificado, de modo que todos os vários arquivos são copiados em versões diferentes e eles não podem trabalhar mais juntos corretamente quando restaurado. O Firebird / InterBase ® Backup faz o backup de todos os arquivos de banco de dados automaticamente.

●As diferentes versões do Firebird / InterBase ® usar diferentes formatos de arquivos de banco de dados, de modo que é impossível copiar um arquivo diretamente de um ambiente de sistema operacional para o formato exigido de outro ambiente de sistema operacional. O Firebird / InterBase ® utilitário de backup permite que um formato de backup transportável, para que este arquivo pode ser restaurado em qualquer desejado Firebird / InterBase ® plataforma. Atenção: Ao fazer o backup e restauração, por exemplo, do InterBase ® 4 para Firebird 1.5,armazenados procedimentos são restaurados como gotas , de modo que eles não podem trabalhar inicialmente.

●O Firebird / InterBase ® descarta backup antigo conjuntos de dados e índices arquivos, resultando em um arquivo de backup menores (consulte acoleta de lixo para mais informações).

●Páginas vazias também são removidos automaticamente durante um backup e restore, o que reduz o tamanho total do banco de dados. Atransação número no TIP é redefinido para zero (o número total de transações que podem ser gravados em um TIP é de aproximadamente 1,3 bilhões!). O cache funciona com muito mais eficiência na sequência de um backup e restauração como as páginas são reajustados. Atenção: No Firebird 1.5 o gerenciador de memória permite que novos conjuntos de dados a ser automaticamente armazenadas em páginas antigas, sem ter que fazer backup e restaurar.

●Durante uma Firebird / InterBase ® Backup a integridade e referências para todos os objetos de banco de dados , por exemplo, domínios , tabelas, índices , visões , gatilhos , procedimentos armazenados , geradores , exceções e permissões , são verificados.

●Execução de um backup e restore é a única forma de alterar posteriormente os parâmetros fundamentais na estrutura de banco de dados, tais como o tamanho da página e distribuição através de arquivos secundários .

Portanto, é recomendável não só para backup, mas também restaurar o banco de dados regularmente (por exemplo, uma vez por mês).

 

Restaurar banco de dados

O IBExpert Serviços de menu item de restauração do banco de dados permite que você restaurar o banco de dados a partir de um arquivo de backup.

A restauração do banco de dados é necessária nas seguintes situações:

●Após cerca de 1,3 bilhão de transações , a fim de redefinir o espaço de transação.

●Após 255 metadados mudanças em uma única tabela, caso contrário, não mais alterações de metadados são possíveis. Por favor, consulte a 253 mudanças de tabela à esquerda para obter mais informações.

●Ao alterar o Firebird / InterBase ® versão que você precisa para fazer o backup da versão antiga e restaurar para o novo número de versão.

●Quando você precisar alterar o tamanho da página de dados.

A principal vantagem de restaurar o banco de dados regularmente é que todos os contadores são definidos de volta, o TIP já está definido de volta para o número mínimo disponível, como é o contador de formato de gravação.

Para automatizar o seu backup e restaurar usar o IBExpertBackupRestore serviço encontrado no menu Serviços IBExpert item HK-Software Serviços do Centro de Controle .

Antes de restaurar um backup do arquivo em um banco de dados, é importante primeiro desconectar o banco de dados ! - Caso contrário, você pode acabar com um banco de dados corrompido deve usuários tentam entrar e executar operações de dados durante a restauração.

O Arquivo página permite as seguintes especificações:

Restaurar em: Selecione a restaurar no banco de dados existente ou criar um novo banco de dados . Ao restaurar no banco de dados existente, selecione a partir da lista de bancos de dados registrados, se restaurar para um novo banco de dados, em seguida, definir o nome do arquivo de banco de dados não esquecendo a unidade e caminho. Ao restaurar em um novo banco de dados, você também pode marcar a opção no canto inferior esquerdo, Registre banco de dados após a restauração , que abre automaticamente o IBExpert dados Register janela após uma restauração bem-sucedida, o que lhe permite registrar imediatamente o seu novo banco de dados para trabalhar com IBExpert .

O nome do arquivo: Especifique o nome do arquivo de backup que será restaurado. O botão [...] para a direita desta linha permite que você encontre um nome existente arquivo, unidade e caminho. Os sufixos . GBK e . FBK são tradicionalmente utilizados, respectivamente, paraInterBase ® e arquivos de backup do Firebird.

As seguintes opções de restauração podem ser verificados / desmarcada como desejava:

●Desativar índices: Se esta opção estiver marcada, dados os índices são desativados durante a restauração. Esta opção é usada para melhorar o desempenho de restauração. Se esta opção não estiver marcada, Firebird / InterBase ® atualiza os índices depois de todos os quadros foram preenchidos com os restaurados linhas . Esta opção pode também ser necessário se a base de dados contém dados com um índice único, mas existem valores na tabela que na verdade não são únicos. Ele também pode ser usado quando o campo de comprimento em uma ou mais tabelas deve ser alterada a posteriori, ou quando não é simplesmente um índice de funcionar devido a algumas inconsistências desconhecidas.

●Não recriar arquivos de sombra: Se esta opção estiver marcada, os arquivos de sombra não são recriados durante a restauração.

●Não cumprir as condições de validade: Quando esta opção estiver marcada, as condições de validade de banco de dados, tais como as restrições sobre os campos ou tabelas não são restaurados. Esta opção é útil se as restrições de validade foram alteradas após os dados já haviam sido inseridos no banco de dados. Quando um banco de dados é restaurado, Firebird / InterBase ® compara cada linha com o metadados , uma mensagem de erro é recebida se os dados incompatíveis foi encontrado. Uma vez que os dados em falta foi corrigida, as restrições podem ser adicionados de volta.

●Comprometer após cada tabela: Se esta opção estiver marcada, o trabalho está comprometida após a restauração de cada tabela. Isso permite que todas essas tabelas para ser restaurado e comprometido onde não há dados corrompidos. Ele restaura metadados e dados para cada mesa, por sua vez, como uma única transação e, em seguida, confirma a transação. Esta opção é útil se os dados corruptos é suspeito no arquivo de backup, ou se o backup não está em execução até a conclusão. Normalmente, o Firebird / InterBase ® restaura todos os metadados e, em seguida, restaura os dados. Se você encontrar problemas ao restaurar seu banco de dados, desative esta opção e tente novamente.

●Substituir banco de dados existente: Se esta opção estiver marcada, o banco de dados restaurado substitui o já existente. Deixando esta opção desmarcada fornece uma medida de proteção de substituir acidentalmente um arquivo de banco de dados.

●Prevenir banco de dados / transação desencadeia a partir de disparo: adicionado no IBExpert versão 2013/02/15. Este é igual aoisc_dpb_no_db_triggers opção em parâmetros de ligação adicionais .

●Use todo o espaço: Esta opção deve ser verificada ao restaurar a base de dados num CD de dados onde a manipulação de pouca ou nenhuma será realizada na base de dados, tal como todo o espaço (isto é, 100%) é então usado, em oposição à habitual de 80% das bases de dados que estão sujeitas a alterações e armazenados em discos rígidos. Utilizando todo o espaço em um banco de dados com inserções regulares, alterações e exclusões irá resultar em um monte de desfragmentação. Se esta opção ser erroneamente ser verificada, pode ser desativado usando GFIX . Alternativamente, realizar a restauração novamente, desta vez com os parâmetros corretos.

●Apenas metadados: Esta opção produz uma cópia vazia da base de dados. Não use esta opção com Substituir banco de dados existente , como você vai acabar com um banco de dados vazio, e todos os seus dados perdidos! Esta opção também pode ser usada para restaurar a estrutura de um banco de dados corrompido , para permitir a análise e reparação, embora o IBExpert menu Ferramentas artigo, Metadados Exract ? , é mais flexível, pois permite-lhe não só extrair os metadados, mas também todos os dados saudáveis ​​assim.

●Tamanho da página: Banco de Dados o tamanho da página em bytes. Esta é a única opção que o tamanho da página para um banco de dados existente a ser alterada. Temos ainda as opções dela para especificar 1K, 2K, 4K, etc No entanto, desde o Firebird 2.1 1K e 2K são automaticamente convertidos para pelo menos 4K. O melhor tamanho de página depende de uma série de fatores discutidos em detalhes emTamanho da página .

●Cliente Biblioteca de Arquivos: Essa é uma possibilidade adicional para especificar uma biblioteca cliente que serão utilizados durante a restauração. Esta opção permite que o usuário especifique se ele requer o InterBase ® ou a biblioteca do cliente Firebird para cada IBExpertconexão. O padrão da biblioteca de cliente é que especificado no menu Options IBExpert item Opções de Ambiente .

●Detalhado: Entrada detalhado para receber um protocolo detalhado do atual processo de restauração de banco de dados, por escrito, informações sobre o status passo-a-passo para o registro de saída. As opções On Screen ou em arquivo (não esquecendo de selecionar ou especificar um nome de arquivo para este protocolo) precisa ser especificado antes de iniciar o backup. Esta opção é útil se o restauro está a falhar, ea razão pela qual precisa ser analisado. Por favor, note que, desde IBExpert versão 2012/11/15, IBExpert agora analisa e recupera mensagens de erro do log de ​​restauração, mesmo que o Verbose opção está desativada. Se forem detectados erros eles serão colocados no final do log e o usuário será alertado sobre possíveis problemas.

●Registre banco de dados após a restauração: Esta opção está disponível somente se o Restore para um novo banco de dados opção foi selecionado na parte superior da base de dados Restore janela. Ao marcar esta opção abre automaticamente o banco de dados do Registro de diálogo após uma restauração bem-sucedida em um novo banco de dados, permitindo que você registre o seu novo banco de dados para o trabalho no IBExpert .

A restauração pode ser então iniciada. Se a opção de protocolo On Screen foi selecionado, o backup é registrado na saída da página.

Em circunstâncias normais, nenhuma das opções de restauração acima devem precisa ser especificado. Se houver suspeita de inconsistências entre os metadados e os dados em si, verifique o commit depois de cada tabela , Desativar Indexes , e não impõem condições de validade de opções.

Usando o registro de banco de dados item de menu, Backup / Restore nomes de arquivo padrão, os caminhos e as unidades podem ser especificado se desejava, juntamente com o padrão de backup e restauração. Esta informação pode ser especificado quando inicialmente registrar um banco de dados no IBExpert (ver Register banco de dados ) ou numa data posterior (ver Informações de Registro de Banco de Dados ).

Tutorial IBExpert – Parte 02 – Backup e Restore

Neste tutorial vamos conhecer alguns dos principais recursos do aplicativo IBExpert, segundo minha concepção. É um tutorial bem ilustrado com informações claras e direcionadas a um publico leigo. Serão abordados assuntos como criação de banco

 

 

O procedimento para efetuar o Backup e Restore no IBExpert é muito simples. Para realizar a cópia de segurança, Acesse no Menu principal a opção Services -> Backup Database, e na janela que se abre informe os seguintes dados:

 

1.Em Select Database, selecione o banco de dados para o qual deseja efetuar a copia de segurança.

2.Na Grade abaixo, já aparece os dados padrão do arquivo a ser gerado. Caso ache necessário poderá ser alterado.

3.Logo abaixo há uma serie de opções que podem ser deixadas como padrão.

4.Em Format, Deixe selecionada a opção Transportable, que indicará que o backup poderá ser transportado.

A opção Output, serve para indicar a forma que será visualizada o procedimento de criação do arquivo de backup. Não é necessário alterar.
 

 
 

Clique no botão Start Backup (Iniciar Reposição), e aguarde a conclusão da cópia de segurança.

 

Para realizar a restauração da copia de segurança, também não há segredo. Basta selecionar no menu principal a opção Services->Restore Database, e siga os seguintes passos:

 

1.Selecione em Restore Into, o banco de dados que de destino onde será restaurado os dados. Poderá ser em um banco existente ou em um novo banco de dados.

2.Em Select Database, informe o caminho do banco de dados a ser restaurado.

3.Ao clicar na grade abaixo, na direita da grade você irá visualizar um botão “...”, onde clicando abrirá uma janela para selecionar o arquivo de backup, para efetuar a restauração.

4.Abaixo da grade há uma série de opções. Deixa como esta e selecione apenas em Page Size o tamanho da paginação do banco. Eu recomendo que selecione em 4096.

5.Clique em Iniciar Copia, para iniciar a restauração do arquivo. Aguarde o termino.
